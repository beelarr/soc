# Research

Use the dependency list from setup. This step decides what to offer the person. It does not install anything, and it does not write a research file.

For the dependencies you found, look for skills and MCP servers published by the same organization that ships the package. Also look for widely used skills from that organization that fit an app built with that package. Offer more than one when more than one fits. A skill whose repository is for contributing to the framework itself is not a skill for an app that depends on it. Do not offer that as the app skill.

Before you offer an MCP or a skill, read the official docs for the version in the manifest. If those docs say it needs a newer version than the manifest declares, do not offer it as something to add. Tell the person the version the docs require and the version the manifest has.

Hand the interview a short offer it can say out loud. Name the dependencies and the skills. For a repo that has both, the sentence is: "I see you have Next.js and FastAPI. Here are skills that you may find useful." Then list each skill or MCP with its publisher, its repository URL, and whether the docs allow it on the declared version.

If you find nothing worth offering, say so. Do not invent a skill.
